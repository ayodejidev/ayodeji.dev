Teams often describe themselves as collaborative while engineers across regions rebuild the same integrations, ownership remains unclear, and shared work becomes difficult to discover or contribute to. This session treats internal collaboration as an operating system rather than a cultural aspiration.

Using Bento, a shared frontend library at Adyen, as a case study, the talk shows how open source practices can turn a shared project into a sustainable collaboration layer. It covers predictable contribution paths, maintainership, documentation as policy, governance, and developer-experience signals that reveal whether collaboration is improving.

## What you will learn

- How to recognize when internal collaboration is failing in practice
- How to structure internal projects for reuse using open source practices
- How to design sustainable contribution and maintainership models
- How to measure impact through onboarding time, review turnaround, visibility, and reuse
